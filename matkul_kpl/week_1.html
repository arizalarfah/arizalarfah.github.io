Indikator A

Definisi dan Jenis Perangkat Lunak

Memahami apa itu perangkat lunak dan mengapa klasifikasinya penting dalam keamanan

Definisi IEEE Std 610.12-1990

Perangkat lunak adalah program komputer, prosedur, dan kemungkinan dokumentasi terkait serta data yang berkaitan dengan pengoperasian sistem komputer. Dalam konteks keamanan, setiap baris kode berpotensi menjadi attack surface yang dapat dieksploitasi.

🖥️

System Software

OS (Windows, Linux, macOS), kernel, firmware, device driver, hypervisor

⚠️ Kerentanan berdampak sistemik
📱

Application Software

Aplikasi web, mobile (Android/iOS), desktop, game, SaaS, enterprise

⚠️ Target serangan paling umum
🔧

Middleware

API gateway, message broker (Kafka), database connector, ESB

⚠️ Celah integrasi sistem
🛠️

Utility & Security Tools

Antivirus, firewall, backup software, monitoring tools, SIEM

⚠️ Jika diretas → blind spot
⚙️

Embedded Software

IoT devices, PLC industrial, firmware router, smart card, ATM

⚠️ Sulit dipatch, ekspos fisik
🔓

Open Source vs Proprietary

OSS: kode terbuka, komunitas review vs Proprietary: kode tertutup, vendor-patch

⚠️ Supply chain attack (Log4Shell)

💡 Relevansi Keamanan: Attack Surface berbeda tiap jenis

System software → privilege escalation | App software → injection, auth bypass | IoT → firmware reverse engineering | Open source → dependency hijacking (contoh: Log4Shell 2021, XZ Utils Backdoor 2024)

Indikator B

Prinsip dan Konsep Keamanan Perangkat Lunak

Fondasi teori yang menjadi landasan seluruh praktik keamanan perangkat lunak

CIA Triad — Pilar Utama Keamanan Informasi
C

🔒 Confidentiality

Menjamin informasi hanya dapat diakses oleh pihak yang berwenang.

Contoh: enkripsi data, access control, klasifikasi data

I

✅ Integrity

Menjamin data tidak dimodifikasi secara tidak sah selama penyimpanan atau transmisi.

Contoh: hash SHA-256, digital signature, checksum

A

⚡ Availability

Menjamin sistem dan data dapat diakses kapan dibutuhkan oleh pihak yang berwenang.

Contoh: DDoS mitigation, redundancy, disaster recovery

Terminologi Kunci
🎯

Threat (Ancaman)

Potensi kejadian yang dapat merusak sistem atau data

Contoh: Hacker, malware, bencana alam, insider threat

🕳️

Vulnerability (Kerawanan)

Kelemahan dalam sistem yang dapat dieksploitasi oleh threat

Contoh: SQL Injection, buffer overflow, misconfiguration

💥

Exploit

Kode atau teknik yang digunakan untuk memanfaatkan vulnerability

Contoh: Metasploit module, PoC code, 0-day exploit

📊

Risk (Risiko)

Probabilitas × Dampak. Risk = Threat × Vulnerability × Asset Value

Contoh: CVSS Score, risk matrix, risk register

🛡️

Attack Surface

Seluruh titik di mana penyerang dapat mencoba masuk atau mengekstrak data

Contoh: API endpoints, UI forms, network ports, physical access

👤

Threat Actor

Individu atau kelompok yang melakukan ancaman terhadap sistem

Contoh: Nation-state, cybercriminal, hacktivist, insider

Indikator C

Peraturan Keamanan Perangkat Lunak di Indonesia

Regulasi yang wajib dipahami oleh pengembang dan praktisi keamanan siber Indonesia

Regulasi Utama
🏛️ UU No. 11/2008 → diubah UU No. 1/2024
Undang-Undang Informasi dan Transaksi Elektronik (ITE)
Mengatur tentang dokumen elektronik, transaksi elektronik, serta larangan konten illegal. Pasal 30-33 terkait akses ilegal dan penyadapan sistem elektronik.
💡 Relevansi: Unauthorized access, hacking dikenai sanksi pidana
🔒 UU No. 27/2022 — Berlaku penuh Oktober 2024
Undang-Undang Pelindungan Data Pribadi (UU PDP)
Mengatur hak subjek data, kewajiban pengendali data, dan sanksi pelanggaran. Software yang memproses data pribadi WNI wajib memenuhi standar keamanan UU PDP.
💡 Relevansi: Wajib enkripsi, privacy by design, lapor insiden 14 hari
📋 PP No. 71/2019
Penyelenggaraan Sistem dan Transaksi Elektronik (PSTE)
Mengatur penyelenggara sistem elektronik (PSE), kewajiban sertifikasi, audit keamanan, dan perlindungan data pengguna sistem elektronik.
💡 Relevansi: PSE wajib audit keamanan berkala
Regulasi BSSN Terkini
🛡️ Peraturan BSSN No. 4/2021
Pedoman Manajemen Keamanan Informasi SPBE
Standar teknis keamanan untuk Sistem Pemerintahan Berbasis Elektronik, mencakup kontrol akses, enkripsi, audit trail, dan patch management.
💡 Relevansi: Benchmark keamanan software pemerintah
📊 Peraturan BSSN No. 7/2024
Penilaian Kesesuaian Kriteria Umum (Common Criteria Indonesia)
Evaluasi keamanan produk teknologi informasi berdasarkan Common Criteria (ISO/IEC 15408). Software pemerintah wajib melewati evaluasi ini.
💡 Relevansi: Sertifikasi keamanan produk software
🔍 Peraturan BSSN No. 8/2024
Audit Keamanan SPBE
Standar dan tata cara pelaksanaan audit keamanan sistem pemerintahan berbasis elektronik secara periodik.
💡 Relevansi: Security audit mandatory untuk sistem pemerintah
🏛️ Perpres No. 82/2022
Perlindungan Infrastruktur Informasi Kritis (PIIK)
Perlindungan infrastruktur informasi kritis nasional di sektor energi, transportasi, keuangan, kesehatan, dan pemerintahan.
💡 Relevansi: Software di sektor kritis wajib standar keamanan tinggi

⚖️ Konsekuensi Hukum Pelanggaran Keamanan Software

UU ITE: Pidana penjara hingga 10 tahun dan denda hingga Rp 10 Miliar untuk akses ilegal dan penyadapan. UU PDP: Denda administratif hingga 2% dari pendapatan tahunan global perusahaan untuk kebocoran data pribadi.

Prinsip Desain Aplikasi yang Aman — Secure SDLC

Mengintegrasikan keamanan ke setiap fase pengembangan perangkat lunak, bukan sebagai afterthought

Fase Secure Software Development Life Cycle (S-SDLC)
1
📋

Requirements

  • Security requirements elicitation
  • Abuse case modeling
  • Compliance mapping (UU PDP, ISO 27001)
  • Privacy requirements
2
🎨

Design

  • Threat modeling (STRIDE)
  • Secure architecture review
  • Data flow diagram + trust boundaries
  • Security design patterns
3
💻

Development

  • Secure coding guidelines
  • Input validation & sanitization
  • Peer code review
  • SAST (Static Analysis)
4
🧪

Testing

  • DAST (Dynamic Analysis)
  • Penetration testing
  • Security regression testing
  • Fuzzing & vulnerability scan
5
🚀

Deployment

  • Secure configuration baseline
  • Secrets management
  • Hardening & minimal footprint
  • CI/CD security gates
6
🔄

Maintenance

  • Patch & vulnerability management
  • Security monitoring & SIEM
  • Incident response
  • Retirement planning

🏗️ 8 Prinsip Desain Aman (Saltzer & Schroeder) — Fondasi S-SDLC

1
Economy of Mechanism
Desain sesederhana mungkin
2
Fail-Safe Defaults
Default = akses ditolak
3
Complete Mediation
Validasi setiap akses
4
Open Design
Keamanan tidak bergantung pada kerahasiaan desain
5
Separation of Privilege
Butuh lebih dari 1 kondisi untuk akses
6
Least Privilege
Hak akses minimal yang diperlukan
7
Least Common Mechanism
Minimalkan mekanisme yang dibagi
8
Psychological Acceptability
Keamanan mudah digunakan

📌 Pergeseran Paradigma: "Shift Left Security"

Penelitian IBM menunjukkan bahwa biaya memperbaiki kerentanan pada fase requirements hanya 1x, pada fase testing menjadi 15x, dan setelah production bisa mencapai 100x lebih mahal. (IBM System Science Institute, 2022)

Studi Kasus

Insiden Keamanan Perangkat Lunak Nyata

Belajar dari kasus nyata untuk memahami dampak kelemahan keamanan software

🔓

Log4Shell (CVE-2021-44228)

Desember 2021 · CVSS: 10.0 (Critical)

Kerentanan Remote Code Execution pada library Apache Log4j 2 (open source, digunakan oleh ratusan juta aplikasi Java). Penyerang cukup mengirim string khusus ke log untuk mengeksekusi kode sembarang.

Supply Chain Open Source RCE Java
Pelajaran: Dependency management kritis. Semua software yang menggunakan library Log4j terdampak — termasuk Apple iCloud, Steam, Minecraft, dan ribuan sistem lain.
🏦

Kebocoran Data BSI (2023)

Mei 2023 · Indonesia · 1.5 TB data

Bank Syariah Indonesia diretas oleh ransomware LockBit 3.0. Data nasabah dan karyawan sebesar 1.5 TB diklaim bocor. Layanan ATM dan mobile banking sempat terganggu beberapa hari.

Ransomware Data Breach Indonesia Financial
Pelajaran: Availability (CIA) terganggu. Backup offline, network segmentation, dan incident response plan sangat krusial untuk sektor keuangan.
🏛️

Kebocoran Data PDNS (2024)

Juni 2024 · Indonesia · 282 instansi

Pusat Data Nasional Sementara (PDNS) diserang Brain Cipher ransomware. Data 282 instansi pemerintah terdampak, termasuk layanan imigrasi dan beasiswa. Tebusan USD 8 juta diminta.

Ransomware Pemerintah Indonesia Availability
Pelajaran: Backup data terenkripsi offline, zero trust architecture, dan patch management reguler sangat penting untuk infrastruktur kritis.
🔑

XZ Utils Backdoor (CVE-2024-3094)

Maret 2024 · Supply Chain · CVSS: 10.0

Penyerang nation-state menyusupkan backdoor ke library kompresi XZ Utils (digunakan oleh Linux). Ditemukan secara kebetulan oleh engineer Microsoft sebelum tersebar luas.

Supply Chain Backdoor Nation-state Linux
Pelajaran: Open source bukan berarti aman otomatis. Software composition analysis (SCA) dan code signing sangat diperlukan dalam DevSecOps.

🎯 Pesan Kunci Pertemuan Ini

Keamanan perangkat lunak bukan hanya tentang teknik — ini tentang mindset. Setiap baris kode yang Anda tulis dapat menjadi pintu masuk bagi penyerang. Dengan memahami regulasi, standar, dan prinsip desain yang tepat, Anda dapat membangun software yang aman by design, bukan aman by afterthought.
