Lab 1 — SAST dengan Semgrep

Static Application Security Testing pada source code DVWA | Estimasi: 50 menit

🎯 Tujuan Lab 1

  • Menginstal dan menjalankan Semgrep dengan rules OWASP Top 10
  • Menganalisis output Semgrep dan memetakan temuan ke OWASP SCP kategori yang sesuai
  • Menulis custom rule Semgrep untuk mendeteksi penggunaan MD5 sebagai password hash
  • Memahami perbedaan severity: ERROR vs WARNING vs INFO

Langkah 1.1 — Install Semgrep

  • 1
    Pastikan Python 3.8+ sudah terinstal: python --version
  • 2
    Install Semgrep melalui pip: jalankan perintah di bawah ini di terminal
  • 3
    Verifikasi instalasi dengan melihat versi Semgrep
# Install Semgrep pip install semgrep # Verifikasi semgrep --version Semgrep 1.x.x

Langkah 1.2 — Download Source Code DVWA

  • 1
    Clone repository DVWA ke direktori lokal Anda
  • 2
    Navigasi ke folder hasil clone — folder ini akan menjadi target scan Semgrep
git clone https://github.com/digininja/DVWA.git cd DVWA ls about.php config dvwa index.php README.md security.php ...

Langkah 1.3 — Scan dengan Rules OWASP Top 10

  • 1
    Jalankan Semgrep dengan konfigurasi rules OWASP Top 10 untuk PHP
  • 2
    Semgrep akan mengunduh rules dari registry dan menjalankan scan — tunggu hingga selesai (1–2 menit)
  • 3
    Perhatikan output: nama file, nomor baris, rule ID, severity, dan pesan
# Scan dengan rules OWASP Top 10 semgrep --config=p/owasp-top-ten ./ # Atau spesifik untuk PHP security semgrep --config=p/php-security ./ # Contoh output yang diharapkan: vulnerabilities/sqli.php 8┆ $query = "SELECT * FROM users WHERE user='$user'"; ... Rule: php.lang.security.injection.tainted-sql-string Severity: ERROR CWE: CWE-89 (SQL Injection) OWASP: A03:2021 login.php 12┆ $pass = md5($password); Rule: php.lang.security.weak-crypto.md5-used-as-password-hash Severity: WARNING CWE: CWE-916 OWASP: A02:2021 Ran 45 rules on 31 files: 12 findings.

Langkah 1.4 — Ekspor Hasil ke JSON

# Export hasil ke JSON untuk dokumentasi semgrep --config=p/owasp-top-ten \ --json -o semgrep-results.json ./ # Lihat ringkasan cat semgrep-results.json | python -m json.tool | head -50

Langkah 1.5 — Buat Custom Rule Semgrep

Custom rule memungkinkan Anda mendeteksi pola kode spesifik yang mungkin tidak dicakup rules bawaan. Buat rule untuk mendeteksi penggunaan fungsi mysql_query() yang sudah deprecated (rentan SQLi).

  • 1
    Buat file custom-rules/no-mysql-deprecated.yaml dengan isi berikut:
# custom-rules/no-mysql-deprecated.yaml rules: - id: no-deprecated-mysql-functions patterns: - pattern-either: - pattern: mysql_query(...) - pattern: mysql_connect(...) - pattern: mysql_real_escape_string(...) message: "Fungsi mysql_* sudah deprecated dan rentan SQLi. Gunakan MySQLi dengan prepared statement." severity: ERROR languages: [php] metadata: cwe: CWE-89 owasp: A03:2021 references: - https://owasp.org/www-project-top-ten
  • 2
    Jalankan scan dengan custom rule:
semgrep --config=custom-rules/ ./

Lab 2 — DAST dengan OWASP ZAP

Dynamic Application Security Testing terhadap DVWA yang sedang berjalan | Estimasi: 60 menit

🎯 Tujuan Lab 2

  • Mengkonfigurasi OWASP ZAP sebagai proxy dan melakukan spider terhadap DVWA
  • Menjalankan Active Scan dan menganalisis alert yang dihasilkan
  • Membandingkan temuan ZAP (DAST) dengan temuan Semgrep (SAST) dari Lab 1
  • Mengekspor laporan ZAP dalam format HTML

Langkah 2.1 — Setup OWASP ZAP

  • 1
    Download dan install OWASP ZAP dari zaproxy.org/download
  • 2
    Buka ZAP → pilih "Manual Explore" di Quick Start tab
  • 3
    Pastikan DVWA berjalan di http://localhost:8080
  • 4
    Di ZAP: masuk ke Tools → Options → Local Proxies → catat port proxy (default: 8090)
  • 5
    Konfigurasi browser untuk menggunakan proxy ZAP: 127.0.0.1:8090

Konfigurasi Browser (Firefox):
Settings → Network Settings → Manual Proxy
HTTP Proxy: 127.0.0.1 | Port: 8090
Centang "Use this proxy server for all protocols"

Untuk HTTPS

Jika DVWA menggunakan HTTPS, import ZAP Root CA Certificate ke browser: ZAP → Tools → Options → Dynamic SSL Certificates → Save → Import ke browser.

Langkah 2.2 — Authenticated Spider (Crawl dengan Login)

  • 1
    Di browser (dengan proxy ZAP aktif), login ke DVWA: http://localhost:8080/login.php menggunakan admin / password
  • 2
    Navigasi ke beberapa halaman DVWA (SQL Injection, XSS, File Upload) agar ZAP merekam endpoint
  • 3
    Di ZAP, klik kanan pada http://localhost:8080 di panel Sites → Attack → Spider → Start Scan
  • 4
    Tunggu spider selesai (lihat tab Spider) — perhatikan daftar URL yang ditemukan

Langkah 2.3 — Active Scan

  • 1
    Di panel Sites, klik kanan http://localhost:8080 → Attack → Active Scan
  • 2
    Pilih Policy: "Default Policy" → klik Start Scan
  • 3
    Tunggu active scan selesai (5–15 menit tergantung jumlah endpoint). Monitor progres di tab Active Scan
  • 4
    Setelah selesai, lihat hasil di tab Alerts — klik setiap alert untuk detail
Catatan Active Scan

Active scan mengirimkan payload berbahaya ke aplikasi target. Hanya jalankan di lingkungan lab/staging yang Anda miliki — tidak pernah di aplikasi production atau tanpa izin tertulis.

Langkah 2.4 — Alternatif: ZAP CLI via Docker

Jika ingin menjalankan ZAP secara headless (tanpa GUI) atau untuk simulasi CI/CD:

# ZAP Full Scan via Docker (headless) # Pastikan DVWA berjalan di host machine docker run --rm -t \ --network host \ ghcr.io/zaproxy/zaproxy:stable \ zap-full-scan.py \ -t http://localhost:8080 \ -r zap-report.html \ -l WARN # Laporan tersimpan di /zap/wrk/ di dalam container # Untuk menyalin ke host: docker run --rm -t \ -v $(pwd):/zap/wrk/ \ --network host \ ghcr.io/zaproxy/zaproxy:stable \ zap-full-scan.py \ -t http://localhost:8080 \ -r zap-report.html PASS: [...] Application Error Disclosure WARN-NEW: SQL Injection [40018] ... WARN-NEW: Cross Site Scripting (Reflected) [40012] ... FAIL-NEW: 0 FAIL-INPROG: 0 WARN-NEW: 8 WARN-INPROG: 0 PASS: 38 IGNORE: 0 INFO: 2

Lab 3 — Dokumentasi Temuan Keamanan

Menyusun laporan temuan profesional berdasarkan hasil Lab 1 & Lab 2 | Estimasi: 40 menit

🎯 Tujuan Lab 3

  • Memilih 2 temuan terbaik dari Lab 1 dan Lab 2 (total 4 temuan) dan mendokumentasikannya secara profesional
  • Mengisi template laporan temuan sesuai format standar yang mencakup: deskripsi, bukti, dampak, CVSS awal, dan rekomendasi
  • Menulis Executive Summary singkat yang merangkum postur keamanan DVWA
  • Menghubungkan temuan dengan OWASP SCP kategori yang seharusnya diterapkan

Format Laporan Temuan (Per Finding)

Isi satu template berikut untuk setiap temuan yang Anda pilih. Duplikasi template ini untuk setiap finding.

📋 Template Laporan Temuan — Finding #1

Judul Temuan
Contoh: SQL Injection pada Parameter 'id' Halaman Login
Sumber Deteksi
Semgrep (SAST) / OWASP ZAP (DAST) / Keduanya
Kategori OWASP
Contoh: A03:2021 — Injection
SCP yang Dilanggar
Contoh: SCP-01 (Input Validation), SCP-11 (Database Security)
CWE
Contoh: CWE-89 — Improper Neutralization of Special Elements used in an SQL Command
Severity
Critical / High / Medium / Low / Informational
URL / File
Contoh: http://localhost:8080/vulnerabilities/sqli/?id= | sqli.php baris 8
Deskripsi
Jelaskan kerentanan dalam 2–3 kalimat: apa yang rentan, bagaimana hal itu terjadi, mengapa berbahaya
Bukti (Evidence)
Payload yang digunakan / output Semgrep / screenshot ZAP Alert. Contoh: Payload ' OR '1'='1 menghasilkan seluruh data user
Dampak (Impact)
Jelaskan konsekuensi jika dieksploitasi: data breach, akses tidak sah, RCE, dll.
CVSS v3.1 (estimasi)
Contoh: AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:N → Skor: 9.1 (Critical)
Rekomendasi
Langkah konkret perbaikan merujuk OWASP SCP. Contoh: (1) Ganti query ke prepared statement (SCP-11), (2) Validasi input hanya angka (SCP-01), (3) Aktifkan WAF untuk layer tambahan
Referensi
OWASP Top 10 A03:2021, CWE-89, OWASP SCP-01/11, semgrep rule ID

Instruksi: Salin template di atas sebanyak 4 kali (untuk 4 finding). Pilih 2 temuan dari Lab 1 (Semgrep) dan 2 temuan dari Lab 2 (ZAP). Prioritaskan temuan dengan severity tertinggi.
