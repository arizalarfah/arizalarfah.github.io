from flask import Flask, request, jsonify import sqlite3, bcrypt app = Flask(__name__) def get_db(): return sqlite3.connect("api.db") @app.route('/api/login', methods=['POST']) def login(): u = request.json.get('username') p = request.json.get('password') row = get_db().execute( "SELECT id, pass_hash, role FROM users WHERE username=?", [u] ).fetchone() if row and bcrypt.checkpw(p.encode(), row[1]): # RENTAN: token "buatan sendiri" tanpa signature, mudah dipalsukan fake_token = f"{row[0]}:{row[2]}" return jsonify(token=fake_token) return jsonify(error="Login gagal"), 401 @app.route('/api/orders/<int:order_id>') def get_order(order_id): # RENTAN: hanya cek header ada isinya, tidak diverifikasi & tidak cek kepemilikan if not request.headers.get('Authorization'): return jsonify(error="Unauthorized"), 401 order = get_db().execute( "SELECT * FROM orders WHERE id=?", [order_id]).fetchone() if not order: return jsonify(error="Not found"), 404 return jsonify(id=order[0], owner_id=order[1], item=order[2], total=order[3]) if __name__ == '__main__': app.run(debug=True, port=5000)

Lab 1 — Menerapkan Autentikasi JWT

Mengganti token palsu dengan JWT yang ditandatangani secara kriptografis | Estimasi: 40 menit

🎯 Tujuan Lab 1

  • Membuktikan token "buatan sendiri" pada versi awal mudah dipalsukan (tanpa signature)
  • Menerapkan penerbitan JWT bertanda tangan (HS256) saat login berhasil
  • Membuat decorator require_auth untuk memverifikasi JWT pada endpoint terproteksi
  • Menguji bahwa token tanpa signature valid ditolak API

Langkah 1.1 — Buktikan Kerentanan Token Palsu

  • 1
    Jalankan api_vulnerable.py, login sebagai alice via POST /api/login
  • 2
    Amati token yang dikembalikan — hanya berupa "1:user", mudah ditebak/dipalsukan
  • 3
    Coba kirim header Authorization: 3:admin secara manual (tanpa login sebagai admin) ke endpoint mana pun yang membutuhkan role admin
curl -X POST http://localhost:5000/api/login \ -H "Content-Type: application/json" \ -d '{"username":"alice","password":"password123"}' {"token": "1:user"} # Token bisa dipalsukan begitu saja tanpa login: curl -H "Authorization: 3:admin" http://localhost:5000/api/admin/stats # Jika endpoint hanya mem-parsing string ini tanpa verifikasi kriptografis → BERHASIL!

Langkah 1.2 — Terbitkan JWT Bertanda Tangan

import jwt, datetime, os JWT_SECRET = os.environ['JWT_SECRET'] @app.route('/api/login', methods=['POST']) def login(): u = request.json.get('username', '') p = request.json.get('password', '') row = get_db().execute( "SELECT id, pass_hash, role FROM users WHERE username=?", [u] ).fetchone() if row and bcrypt.checkpw(p.encode(), row[1]): payload = { 'sub': row[0], 'role': row[2], 'iat': datetime.datetime.utcnow(), 'exp': datetime.datetime.utcnow() + datetime.timedelta(minutes=15) } token = jwt.encode(payload, JWT_SECRET, algorithm='HS256') return jsonify(access_token=token, expires_in=900) return jsonify(error="Login gagal"), 401

Langkah 1.3 — Decorator Verifikasi Token

from functools import wraps def require_auth(f): @wraps(f) def decorated(*args, **kwargs): auth = request.headers.get('Authorization', '') if not auth.startswith('Bearer '): return jsonify(error="Token tidak ditemukan"), 401 token = auth.replace('Bearer ', '') try: payload = jwt.decode(token, JWT_SECRET, algorithms=['HS256']) except jwt.ExpiredSignatureError: return jsonify(error="Token kedaluwarsa"), 401 except jwt.InvalidTokenError: return jsonify(error="Token tidak valid"), 401 request.user = payload return f(*args, **kwargs) return decorated

Lab 2 — Otorisasi Objek (Anti-BOLA) & Kontrol Peran

Menutup celah BOLA dan BFLA pada endpoint orders & admin | Estimasi: 40 menit

🎯 Tujuan Lab 2

  • Membuktikan endpoint /api/orders/<id> rentan BOLA pada versi awal
  • Menambahkan verifikasi kepemilikan (owner_id) sebelum mengembalikan data
  • Membuat decorator require_role untuk endpoint khusus admin (anti-BFLA)
  • Menguji ulang menggunakan token milik user berbeda

Langkah 2.1 — Buktikan BOLA pada Versi Awal

  • 1
    Login sebagai alice (owner order id=1 dan 3), dapatkan token
  • 2
    Gunakan token alice untuk mengakses GET /api/orders/2 (milik bob)
  • 3
    Amati bahwa data order milik bob tetap dapat diakses — inilah BOLA (API1:2023)

Langkah 2.2 — Perbaiki dengan Verifikasi Kepemilikan

@app.route('/api/orders/<int:order_id>') @require_auth @limiter.limit("60 per minute") def get_order(order_id): order = get_db().execute( "SELECT * FROM orders WHERE id=? AND owner_id=?", [order_id, request.user['sub']] ).fetchone() if not order: # 404 untuk KEDUA kasus: tidak ada / bukan milik user return jsonify(error="Not found"), 404 return jsonify(id=order[0], item=order[2], total=order[3])

Langkah 2.3 — Kontrol Peran untuk Endpoint Admin (Anti-BFLA)

def require_role(role): def decorator(f): @wraps(f) def decorated(*args, **kwargs): if request.user.get('role') != role: return jsonify(error="Forbidden"), 403 return f(*args, **kwargs) return decorated return decorator @app.route('/api/admin/stats') @require_auth @require_role('admin') def admin_stats(): total_orders = get_db().execute("SELECT COUNT(*) FROM orders").fetchone()[0] return jsonify(total_orders=total_orders)

Langkah 2.4 — Uji Ulang dengan Postman/curl

# Login sebagai alice, simpan access_token TOKEN=$(curl -s -X POST http://localhost:5000/api/login \ -H "Content-Type: application/json" \ -d '{"username":"alice","password":"..."}' | jq -r .access_token) # Coba akses order milik bob (id=2) — harus ditolak curl -H "Authorization: Bearer $TOKEN" http://localhost:5000/api/orders/2 {"error": "Not found"} ← 404, BOLA berhasil ditutup # Coba akses endpoint admin dengan token alice (role: user) curl -H "Authorization: Bearer $TOKEN" http://localhost:5000/api/admin/stats {"error": "Forbidden"} ← 403, BFLA berhasil ditutup

Lab 3 — Pengujian Sistematis Keamanan API

Token tampering, expired token, rate limiting, dan data exposure | Estimasi: 40 menit

🎯 Tujuan Lab 3

  • Menguji ketahanan API terhadap token yang dimodifikasi (tampering)
  • Menguji penanganan token kedaluwarsa
  • Memverifikasi rate limiting aktif pada endpoint login & orders
  • Memeriksa response API tidak membocorkan field internal (pass_hash, dsb)

Langkah 3.1 — Uji Token Tampering

  • 1
    Ambil access_token hasil login alice, buka jwt.io, tempel token untuk melihat payload
  • 2
    Salin bagian header & payload, ubah "role":"user" menjadi "role":"admin", encode ulang ke Base64URL
  • 3
    Gabungkan kembali header.payload dengan signature LAMA (tidak ditandatangani ulang) menjadi token baru
  • 4
    Kirim token hasil modifikasi ke /api/admin/stats, catat responsnya
curl -H "Authorization: Bearer <token_yang_dimodifikasi>" \ http://localhost:5000/api/admin/stats {"error": "Token tidak valid"} # HASIL DIHARAPKAN: 401 — signature tidak cocok dengan payload baru

Langkah 3.2 — Uji Expired Token

# Untuk pengujian cepat, ubah sementara masa berlaku token menjadi 5 detik # di kode: timedelta(seconds=5), lalu: TOKEN=$(curl -s -X POST http://localhost:5000/api/login -d '...' | jq -r .access_token) sleep 6 curl -H "Authorization: Bearer $TOKEN" http://localhost:5000/api/orders/1 {"error": "Token kedaluwarsa"} # Kembalikan nilai exp ke 15 menit setelah pengujian selesai

Langkah 3.3 — Uji Rate Limiting pada Login

for i in {1..7}; do curl -s -o /dev/null -w "Percobaan $i: %{http_code}\n" \ -X POST http://localhost:5000/api/login \ -H "Content-Type: application/json" \ -d '{"username":"alice","password":"salah"}' done Percobaan 1: 401 Percobaan 2: 401 ... Percobaan 6: 429 ← rate limit aktif

Langkah 3.4 — Uji Excessive Data Exposure

  • 1
    Periksa response JSON dari /api/orders/<id> dan endpoint profil pengguna
  • 2
    Pastikan tidak ada field pass_hash, kunci internal, atau data user lain yang ikut terkirim
