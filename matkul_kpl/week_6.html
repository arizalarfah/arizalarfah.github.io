Blok 1 — Injeksi

Injeksi pada Aplikasi Mobile

OWASP Mobile M4 — Insufficient Input/Output Validation | CWE-89, CWE-94

Jenis Injeksi pada Mobile

1. SQL Injection (SQLite)

Aplikasi Android umumnya menggunakan SQLite sebagai database lokal. Query yang dibangun dengan konkatenasi string rentan terhadap SQLi.

Severity: HIGH CWE-89

2. Intent Injection

Activity/Service yang diekspor tanpa validasi dapat menerima Intent dari aplikasi jahat, memicu aksi tak terduga atau membocorkan data.

Severity: MEDIUM CWE-94

3. Content Provider Injection

Content Provider yang salah dikonfigurasi (exported=true tanpa permission) memungkinkan query berbahaya ke database melalui URI.

Severity: HIGH CWE-610

Pola Kode Rentan vs Aman

Kode Rentan — SQL Injection

Konkatenasi langsung input user ke query SQL

// RENTAN — jangan gunakan ini String query = "SELECT * FROM users WHERE " + "username='" + username + "'"; db.rawQuery(query, null);
Kode Aman — Parameterized Query
// AMAN — gunakan parameterized query String query = "SELECT * FROM users WHERE username=?"; db.rawQuery(query, new String[]{username});

Kunci Mitigasi: Selalu gunakan ? placeholder dan selectionArgs[] pada query SQLite Android. Terapkan juga validasi input dan prinsip least privilege pada Content Provider.

Blok 1 — Pengujian SQLi

Pengujian SQL Injection pada Aplikasi Android

Metodologi dan teknik menggunakan ADB, Drozer, dan analisis statis

Alur Pengujian SQLi Mobile

1
Recon — Identifikasi Attack Surface

Decompile APK (jadx/apktool), temukan penggunaan rawQuery, execSQL

2
Identifikasi Content Provider

Cari exported=true di AndroidManifest.xml

3
Uji dengan Drozer / ADB

Query langsung ke Content Provider dengan payload SQLi

4
Dokumentasi Temuan

Catat URI, payload, hasil, severity (OWASP Risk Rating)

Contoh Pengujian dengan Drozer

# Temukan semua Content Providers dz> run app.provider.finduri com.target.app content://com.target.app.provider/users content://com.target.app.provider/notes # Query normal dz> run app.provider.query content://com.target.app.provider/users --selection "1=1" | id | username | password_hash | | 1 | admin | 5f4dcc3b5aa... | # Uji SQLi — UNION-based dz> run app.provider.query content://com.target.app.provider/users --selection "1=1) UNION SELECT ..."
Etika Pengujian

Hanya lakukan pengujian pada aplikasi milik sendiri atau yang telah mendapat izin tertulis. Gunakan emulator/device khusus pengujian, bukan device produksi.

Blok 1 — Intent & IPC

Intent Injection & Eksploitasi Deep Link

Kerawanan pada mekanisme IPC Android — Activity, Service, Broadcast Receiver

Permukaan Serangan IPC Android

Exported Activity

Activity dengan android:exported="true" tanpa permission check dapat dipanggil langsung oleh aplikasi lain. Penyerang bisa melompati autentikasi atau memicu aksi sensitif.

# Kirim Intent ke exported Activity adb shell am start -n \ com.target.app/.AdminActivity \ -e "action" "deleteAllData"

Deep Link Hijacking

URL scheme yang tidak divalidasi dapat disalahgunakan. Misalnya myapp://transfer?amount=1000&to=attacker jika parameter tidak diverifikasi ulang.

Pengujian Exported Components

# Cari exported components dengan Drozer dz> run app.package.attacksurface com.target.app Attack Surface: 5 activities exported 2 broadcast receivers exported 1 content provider exported # Cek Activity yang bisa diakses tanpa auth dz> run app.activity.start --component com.target.app .TransferActivity --extra string toAccount "attacker123"

Blok 2 — Autentikasi

Broken Authentication pada Aplikasi Mobile

OWASP Mobile M3 — Insecure Authentication | CWE-287, CWE-798

Pola Kelemahan Autentikasi Mobile

Hardcoded Credentials (M1)

API key, password, atau token yang ditulis langsung dalam source code APK — mudah diekstrak via decompile (jadx).

// Ditemukan di decompile jadx: private static final String API_KEY = "sk_live_abc123..."; private static final String DB_PASS = "admin@1234";

Weak Session Management

  • Token sesi tidak kedaluwarsa (no expiry)
  • Token disimpan di SharedPreferences tanpa enkripsi
  • Token sama digunakan ulang setelah logout
  • Token prediktabel (sequential ID, timestamp)

Biometric Bypass

Implementasi biometrik yang tidak memvalidasi result server-side — penyerang bisa memodifikasi return value via Frida.

Pengujian Autentikasi Mobile

1. Analisis Statis (APK)

  • Decompile APK dengan jadx-gui
  • Cari: password, secret, apikey, token
  • Periksa BuildConfig dan strings.xml
  • Analisis network calls untuk parameter auth

2. Analisis Dinamis (Runtime)

  • Intercept traffic dengan Burp Suite + proxy
  • Manipulasi token/session di request
  • Hook fungsi auth dengan Frida
  • Cek SharedPreferences: adb shell cat /data/data/pkg/shared_prefs/
MSTG Test Cases

MSTG-AUTH-1: Verify password policy enforcement
MSTG-AUTH-2: Verify session tokens are invalidated on logout
MSTG-AUTH-3: Verify biometric auth uses server-side verification

Blok 2 — Data Storage

Insecure Data Storage pada Android

OWASP Mobile M9 / M2 — Data sensitif tersimpan tanpa proteksi memadai | CWE-312

Lokasi Penyimpanan Rentan

LokasiMasalah UmumRisk
SharedPreferences Plaintext token, password hash, PII HIGH
SQLite Database Data tidak terenkripsi, world-readable HIGH
External Storage File di /sdcard/ dapat dibaca semua app HIGH
Logcat / Logs Data sensitif dicetak ke log debug MED
Clipboard Password di-copy masuk clipboard MED
Backup allowBackup=true tanpa enkripsi MED

Teknik Pemeriksaan Data Storage

# Periksa SharedPreferences via ADB adb shell run-as com.target.app \ cat shared_prefs/app_prefs.xml <string name="auth_token">eyJhb...</string> <string name="user_password">P@ss123</string> # Dump SQLite database adb shell run-as com.target.app \ sqlite3 databases/userdata.db \ ".dump" # Cek log sensitif adb logcat | grep -i "password\|token\|secret"

Solusi: Gunakan Android Keystore System untuk menyimpan kunci kriptografi. Enkripsi database dengan SQLCipher. Hindari menyimpan data sensitif di SharedPreferences plaintext. Set android:allowBackup="false" untuk data sensitif.

Tools & Setup

Tools Pengujian Keamanan Aplikasi Mobile

Ekosistem alat untuk analisis statis, dinamis, dan runtime pada Android

Analisis Statis (SAST)

MobSF (Mobile Security Framework)

Framework all-in-one untuk analisis statis & dinamis APK/IPA. Menghasilkan laporan otomatis mencakup manifest, kode, library, dan kerentanan umum. Tersedia via web UI di localhost:8000.

Open Source Python SAST+DAST
Analisis Dinamis (DAST)

Drozer

Framework pengujian keamanan Android via IPC. Memungkinkan interaksi langsung dengan Content Provider, Activity, Service, dan Broadcast Receiver dari luar aplikasi. Ideal untuk pengujian attack surface.

Open Source Python IPC Testing
Runtime Manipulation

Frida

Dynamic instrumentation toolkit. Memungkinkan hooking fungsi pada runtime — bypass SSL pinning, manipulasi return value, intercept method calls. Sangat powerful untuk bypass security control.

Open Source JavaScript Hooking
Decompiler & Shell

Jadx + ADB Shell

Jadx — decompile APK ke kode Java/Kotlin yang dapat dibaca. Sangat baik untuk mencari hardcoded secrets dan logika auth. ADB — Android Debug Bridge untuk akses filesystem, log, dan eksekusi perintah pada device/emulator.

Open Source Static Analysis CLI
Setup Lab

Gunakan Android Studio Emulator (API 28–33, Google APIs) atau device fisik dengan USB Debugging aktif. Install DIVA Android (Damn Insecure and Vulnerable App) sebagai target latihan.

Kuis Interaktif — Pertemuan 6

5 soal pilihan ganda · Sub-CPMK 262.1

Soal 1 dari 5
Database lokal yang paling umum digunakan pada aplikasi Android dan rentan terhadap SQL Injection jika tidak menggunakan parameterized query adalah…
Benar! SQLite adalah database embedded yang digunakan secara lokal di Android. Kerentanan muncul saat menggunakan rawQuery() dengan konkatenasi string langsung.
Kurang tepat. Jawaban yang benar adalah SQLite — database lokal embedded yang digunakan di hampir semua aplikasi Android.
Soal 2 dari 5
Kategori OWASP Mobile Top 10 yang mencakup kelemahan autentikasi seperti hardcoded credentials dan biometric bypass adalah…
Benar! M3 mencakup kelemahan autentikasi termasuk hardcoded credentials (overlap M1), session yang tidak kedaluwarsa, dan biometric bypass.
Kurang tepat. Jawaban yang benar adalah M3 — Insecure Authentication/Authorization, yang mencakup berbagai kelemahan mekanisme autentikasi.
Soal 3 dari 5
Tool yang tepat untuk menguji attack surface Android melalui IPC (Content Provider, Activity, Service) secara dinamis adalah…
Benar! Drozer adalah framework khusus untuk menguji komponen Android via IPC — bisa query Content Provider, mengirim Intent ke Activity/Service, dan menemukan exported components yang rentan.
Kurang tepat. Drozer adalah tool yang tepat untuk IPC testing di Android. Burp Suite digunakan untuk intercepting HTTP traffic, bukan IPC.
Soal 4 dari 5
Penyimpanan data sensitif manakah yang PALING BERBAHAYA karena dapat diakses oleh semua aplikasi lain yang memiliki permission READ_EXTERNAL_STORAGE?
Benar! External Storage (/sdcard/) bisa diakses oleh aplikasi lain dengan permission READ_EXTERNAL_STORAGE. Tidak boleh menyimpan data sensitif di sana tanpa enkripsi tambahan.
Kurang tepat. External Storage (/sdcard/) adalah yang paling berbahaya karena accessible oleh aplikasi lain. Android Keystore justru paling aman.
Soal 5 dari 5
Kategori MSTG yang mencakup test case untuk memeriksa keamanan penyimpanan data lokal (SharedPreferences, SQLite, External Storage) adalah…
Benar! MSTG-STORAGE mencakup semua test case terkait penyimpanan data — SharedPreferences, database, external storage, logs, dan backup.
Kurang tepat. MSTG-STORAGE adalah kategori yang tepat untuk pengujian keamanan penyimpanan data lokal di aplikasi mobile.
