Blok 1 — Kriptografi

Insufficient Cryptography — OWASP Mobile M10

Penggunaan algoritma kriptografi lemah, kunci hardcoded, atau implementasi yang salah | CWE-327

Pola Kerentanan Kriptografi Mobile

1. Algoritma Usang/Lemah

  • MD5/SHA1 untuk hashing password — dapat di-crack dengan rainbow table
  • DES/3DES untuk enkripsi data — kunci 56-bit, tidak aman
  • RC4 — stream cipher dengan kelemahan bias
  • AES-ECB mode — pola terlihat dalam ciphertext

2. Kunci yang Ditanam Keras

  • Secret key/IV ditulis langsung dalam kode Java/Kotlin
  • Disimpan di strings.xml atau BuildConfig
  • Mudah diekstrak saat APK di-decompile dengan jadx

3. IV/Salt Statis atau Tidak Ada

Initialization Vector (IV) yang sama digunakan berulang, atau tidak ada salt pada hashing password — memungkinkan serangan replay dan rainbow table.

Contoh Kode Rentan vs Aman

Kode Rentan — MD5 Password Hashing
// RENTAN — MD5 tanpa salt MessageDigest md = MessageDigest.getInstance("MD5"); byte[] hash = md.digest(password.getBytes()); // Sama dengan bcrypt cracking online! // RENTAN — Hardcoded AES key private static final byte[] KEY = "MySecretKey12345".getBytes(); Cipher c = Cipher.getInstance("AES/ECB/PKCS5Padding");
Kode Aman
// AMAN — BCrypt dengan salt otomatis // Gunakan library: mindrot.jbcrypt String hashed = BCrypt.hashpw(password, BCrypt.gensalt(12)); // AMAN — AES-GCM dengan key dari Keystore KeyGenerator kg = KeyGenerator.getInstance("AES", "AndroidKeyStore"); // Key disimpan di hardware-backed Keystore
Blok 1 — Pengujian Crypto

Pengujian Kriptografi Mobile

Analisis statis dengan Jadx dan analisis dinamis dengan Frida untuk mendeteksi kelemahan kriptografi

Analisis Statis — Jadx

Decompile APK dan cari penggunaan API kriptografi:

# Buka jadx-gui, load APK, gunakan Find Usage # Keyword pencarian di source code: MessageDigest.getInstance("MD5") MessageDigest.getInstance("SHA1") Cipher.getInstance("DES") Cipher.getInstance("AES/ECB") "AES/CBC" + hardcoded IV SecretKeySpec(keyBytes, "AES") # Cari juga di strings.xml dan BuildConfig: grep -r "secret\|key\|encrypt\|aes\|des" \ res/values/strings.xml
Tanda Bahaya

Temuan SecretKeySpec(hardcoded_bytes, "AES") atau IvParameterSpec(new byte[]{0,0,0,...}) adalah indikator kuat kerentanan kriptografi serius.

Analisis Dinamis — Frida Hooking

Hook API kriptografi Android saat runtime untuk menangkap key dan plaintext:

// frida-hook-crypto.js Java.perform(function() { var MessageDigest = Java.use( 'java.security.MessageDigest'); MessageDigest.getInstance.overload('java.lang.String') .implementation = function(algo) { console.log("[*] MessageDigest.getInstance: " + algo); return this.getInstance(algo); }; var Cipher = Java.use('javax.crypto.Cipher'); Cipher.getInstance.overload('java.lang.String') .implementation = function(transform) { console.log("[*] Cipher: " + transform); return this.getInstance(transform); }; });
# Jalankan script Frida: frida -U -l frida-hook-crypto.js \ -f com.target.app --no-pause [*] Cipher: AES/ECB/PKCS5Padding ← RENTAN! [*] MessageDigest.getInstance: MD5
Blok 2 — Otorisasi

Otorisasi Tidak Tepat pada Aplikasi Mobile

OWASP Mobile M3 (Authorization) | CWE-862, CWE-639 — Broken Object Level Authorization

Jenis Kelemahan Otorisasi Mobile

IDOR — Insecure Direct Object Reference

Aplikasi menggunakan ID yang dapat ditebak/dimanipulasi untuk mengakses data pengguna lain. Contoh: mengganti userId=101 menjadi userId=102 di request API.

# Request normal pengguna A: GET /api/profile?userId=101 # IDOR — akses data pengguna B: GET /api/profile?userId=102

Privilege Escalation

Pengguna biasa dapat mengakses endpoint admin karena server tidak memvalidasi role. Misalnya: /api/admin/deleteUser bisa diakses oleh non-admin.

Missing Authorization Checks

API endpoint tidak memvalidasi apakah user yang terautentikasi berhak mengakses resource. Token valid tapi tidak ada pengecekan kepemilikan data.

Dampak & Contoh Nyata

Kasus: Gojek API IDOR (2019)

Peneliti menemukan IDOR pada API Gojek — memungkinkan akses profil, riwayat order, dan informasi driver pengguna lain hanya dengan mengganti ID order di request.

IDOR Bug Bounty Data Breach

Kasus: Banking App JWT Bypass

Aplikasi mobile bank menggunakan JWT dengan algoritma "none" — server menerima token tanpa signature, memungkinkan penyerang membuat token untuk akun siapa pun.

JWT Bypass Privilege Escalation

Mitigasi: Validasi otorisasi di sisi server untuk setiap request. Gunakan RBAC (Role-Based Access Control). Jangan mengandalkan client-side untuk penegakan hak akses. Validasi kepemilikan resource per request.

Analisis JWT & Pengujian IDOR

# Decode JWT (tanpa verifikasi) # Header.Payload.Signature eyJhbGciOiJIUzI1NiJ9 ← Header eyJ1c2VySWQiOiIxMDEiLCJyb2xlIjoidXNlciJ9 ← Payload: {"userId":"101","role":"user"} # Uji "alg:none" attack # Modifikasi header ke {"alg":"none"} # Hapus signature, kirim ke server # Pengujian IDOR dengan Burp Intruder # Ganti userId=§101§ → range 100-200 GET /api/transactions?userId=§101§ # Response 200 = IDOR ditemukan
Perhatian Etika

Pengujian IDOR hanya dilakukan pada akun milik sendiri (akun pengujian) atau dengan izin tertulis. Jangan mengakses data akun pengguna nyata lain tanpa persetujuan.

Tools Lanjutan

Tools Lanjutan Pengujian Keamanan Mobile

Jadx, Objection, Frida, dan Burp Suite — ekosistem pengujian runtime & analisis mendalam

DECOMPILER

Jadx-GUI

Decompile APK ke kode Java/Kotlin yang mudah dibaca. Mendukung pencarian teks di seluruh codebase — ideal untuk mencari hardcoded keys, algoritma crypto, dan logika otorisasi.

# CLI mode jadx -d output/ app.apk grep -r "Cipher\|AES\|MD5" output/
RUNTIME EXPLORATION

Objection

Framework runtime berbasis Frida dengan interface yang lebih mudah. Memudahkan bypass SSL pinning, root detection, eksplorasi file, dan analisis class yang dimuat saat runtime.

objection -g com.target.app explore objection> android sslpinning disable objection> android root disable objection> android hooking list classes
DYNAMIC INSTRUMENTATION

Frida

Hook dan modifikasi perilaku fungsi saat runtime. Dapat menangkap parameter/return value, bypass security control, dan trace eksekusi program secara real-time dengan JavaScript.

frida-ps -U # daftar proses Android frida -U -l script.js -f com.app
HTTP PROXY & API TESTING

Burp Suite (Community)

Intercept dan modifikasi HTTP/HTTPS request dari aplikasi mobile. Sangat efektif untuk pengujian IDOR (Intruder), analisis JWT (Decoder tab), dan testing business logic API.

# Useful extensions: JWT Editor (JWT analysis/modify) Autorize (authorization testing) Param Miner (hidden parameters)
Blok 3 — Laporan

Struktur Laporan Pengujian Keamanan (Sub-CPMK 262.2)

Format laporan pengujian keamanan profesional yang diakui industri

Bagian Utama Laporan

1. Executive Summary

  • Tujuan dan ruang lingkup pengujian
  • Metodologi yang digunakan
  • Ringkasan temuan (jumlah per severity)
  • Rekomendasi strategis (2–3 kalimat)

2. Metodologi & Scope

  • Target: nama aplikasi, versi, platform
  • Metode: SAST, DAST, MSTG test cases
  • Tools: MobSF, Drozer, Frida, Burp
  • Periode pengujian & batasan

3. Temuan (Findings)

  • Setiap temuan: ID, nama, kategori, severity
  • Deskripsi teknis + bukti (screenshot, payload)
  • Dampak bisnis dan teknis
  • CVSS Score + OWASP Risk Rating

4. Rekomendasi

  • Mitigasi spesifik per temuan
  • Prioritas berdasarkan severity
  • Referensi standar (OWASP, CWE, NIST)

Severity Classification

LevelCVSS RangeSLA Fix
CRITICAL 9.0 – 10.0 24 jam
HIGH 7.0 – 8.9 1 minggu
MEDIUM 4.0 – 6.9 1 bulan
LOW 0.1 – 3.9 Next Sprint
INFO 0.0 Best Effort

CVSS vs OWASP Risk Rating: Gunakan OWASP Risk Rating (Mg 5) untuk menghitung severity dari faktor Likelihood + Impact. Sertakan juga CVSS Base Score jika laporan untuk auditor eksternal.

Tips Laporan Profesional

Pastikan setiap temuan memiliki: bukti yang jelas (screenshot/payload), langkah reproduksi (proof of concept), dan rekomendasi spesifik — bukan hanya "fix the vulnerability".

Studi Kasus

Studi Kasus: Temuan Kriptografi & Otorisasi di Fintech App

FinPay Mobile App v3.2 (Android) — Authorized Security Assessment

Target: FinPay Mobile App v3.2

Aplikasi fintech untuk transfer dan pembayaran digital. Assessment dilakukan tim keamanan internal sebelum rilis ke production.

Temuan Kriptografi (FIND-007)

AES-ECB Mode pada Enkripsi PIN

Lokasi: PinManager.java:89
Bukti Statis (Jadx):

Cipher.getInstance("AES/ECB/PKCS5Padding"); private byte[] KEY = "FinPay2024Key128".getBytes();

Dampak: PIN 4-digit hanya memiliki 10.000 kemungkinan. ECB mode tidak menggunakan IV — PIN yang sama menghasilkan ciphertext yang sama, memungkinkan serangan analisis frekuensi.

Severity: HIGH (7.5)

Temuan Otorisasi (FIND-008)

IDOR pada API Riwayat Transaksi

Lokasi: API /api/v2/transactions

# Request akun sendiri: GET /api/v2/transactions?accountId=FP10045 # IDOR — ganti ID ke akun lain: GET /api/v2/transactions?accountId=FP10046 HTTP 200 — Data transaksi akun lain!

Dampak: Penyerang dapat melihat seluruh riwayat transaksi, saldo, dan data keuangan pengguna lain. Potensi pelanggaran UU PDP dan reputasi bisnis.

Severity: HIGH (8.0)

Rekomendasi

Ganti AES-ECB dengan AES-GCM. Gunakan Android Keystore untuk menyimpan kunci. Tambahkan server-side ownership check pada setiap API endpoint dengan parameter accountId.

Kuis Interaktif — Pertemuan 7

5 soal pilihan ganda · Sub-CPMK 262.1 & 262.2

Soal 1 dari 5
Mengapa MD5 TIDAK aman digunakan untuk menyimpan password pengguna?
Benar! MD5 terlalu cepat — dapat menghash miliaran percobaan per detik dengan GPU. Ditambah tersedia database rainbow table online. Password hashing harus menggunakan fungsi lambat: bcrypt, argon2, atau PBKDF2.
Kurang tepat. MD5 tidak aman karena TERLALU CEPAT, bukan lambat. Kecepatan membuatnya rentan terhadap brute force dengan GPU dan rainbow table attack.
Soal 2 dari 5
Kategori OWASP Mobile Top 10 mana yang mencakup kerentanan hardcoded API key dalam kode APK?
Benar! M1 — Improper Credential Usage mencakup hardcoded credentials (API keys, passwords, tokens) yang ditemukan dalam kode APK. Mudah diekstrak dengan jadx atau strings command.
Kurang tepat. Hardcoded API key masuk ke M1 — Improper Credential Usage. M9 untuk data storage, M10 untuk algoritma crypto yang lemah.
Soal 3 dari 5
Tool yang digunakan untuk melakukan hooking fungsi kriptografi Android secara real-time (dynamic instrumentation) adalah…
Benar! Frida adalah dynamic instrumentation toolkit yang memungkinkan hooking fungsi Java/Native saat runtime. Objection (berbasis Frida) menyediakan interface yang lebih mudah untuk operasi umum seperti SSL pinning bypass.
Kurang tepat. Frida adalah tool untuk dynamic instrumentation/hooking. Jadx adalah decompiler statis, MobSF untuk analisis otomatis, Drozer untuk IPC testing.
Soal 4 dari 5
Bagian laporan pengujian keamanan yang berisi ringkasan temuan, metodologi, dan rekomendasi strategis yang ditujukan untuk pimpinan/manajemen adalah…
Benar! Executive Summary adalah bagian yang ditulis untuk audiens non-teknis/manajemen — berisi ringkasan temuan per severity, dampak bisnis, dan rekomendasi strategis tanpa detail teknis mendalam.
Kurang tepat. Executive Summary adalah bagian untuk manajemen. Finding Detail dan Technical Appendix untuk tim teknis. PoC adalah bukti eksploitasi, bukan bagian ringkasan.
Soal 5 dari 5
Serangan IDOR (Insecure Direct Object Reference) pada API mobile terjadi karena…
Benar! IDOR terjadi karena server hanya memeriksa apakah user terautentikasi, tapi tidak memvalidasi apakah user tersebut berhak mengakses resource spesifik yang diminta. Solusi: server-side ownership check per request.
Kurang tepat. IDOR terjadi karena tidak ada validasi kepemilikan (ownership validation) di sisi server. Bukan masalah enkripsi atau protokol HTTP.
